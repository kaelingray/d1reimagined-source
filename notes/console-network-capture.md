# Xbox 360 reference network capture (2026-09-23)

The user's Xbox 360 reached Destiny's character screen while routed through the PC's spare Ethernet adapter. The PC's existing router connection was `Ethernet 2`; the spare console-facing port was `Ethernet`. Windows Internet Connection Sharing provided `192.168.137.1` to the Xbox. The Xbox received `192.168.137.11`. Built-in `pktmon` recorded only the first 128 bytes of each matching packet and capped the trace at 64 MB. Sharing was disabled after the capture; the spare port returned to its prior link-local address. Private raw captures are kept under `D:\Destiny360\LOGS\console-network-capture`, outside this Git workspace.

The first trace, moved into `network-test-only`, covers the Xbox Live network test. It includes Xbox service DNS questions such as `notice.xbox.com`, `login.live.com`, and download hosts. The second trace covers the user's Destiny launch and successful arrival at the character screen. In addition to Xbox service names, it has DNS questions for `www6.signon.gravityshavings.net` and `cdn.deadorbit.net`. These are consistent with Destiny/Bungie service and content infrastructure, but the limited snapshot and filtering do not show a complete request/response exchange. The game may also reuse existing connections or cached DNS results. Do not claim that these two hosts are the full protocol.

The metadata-only analyzer is `scripts/AnalyzeConsoleTrace.py`; it intentionally prints endpoints and DNS names, never raw payloads. The capture/rollback helper is `scripts/ConsoleNetworkCapture.ps1`. The tested sequence was Start, Xbox network test, Stop, then Start, Destiny launch, Stop. Both Stop runs logged `Original Internet sharing state restored` and produced pcapng files. The helper checks the exact adapter names and that both links are active before it changes sharing.

The Xenia Test010 trace had no guest-visible server request before canary, and Test011 showed that an active Ethernet-link bit alone did not help. The console capture therefore points toward Xenia's missing online profile/network API behavior as an early priority; it does not imply that simply redirecting DNS to Bungie servers will work. Any future live-service experiment should use authorized accounts and avoid publishing credentials or account identifiers from captures.
