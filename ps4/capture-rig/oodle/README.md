## What it does

Runs Destiny's **own** Oodle decoder out of `dumps/patch-01.29-CUSA00219/eboot.bin` under **Unicorn
CPU emulation** - no native execution of foreign code, no guessed Oodle format, no reimplementation,
and no third-party decoder of any licence.

```
0x1267120  query decoder scratch size
0x12671A0  init decoder
0x12672E0  OodleLZDecoder_DecodeSome
```

The harness maps the eboot text, applies `DT_SCE_RELA` relocations, provides a stack/heap/in/out
arena, stubs the allocator and `mem*` imports, and calls those three by address.

## The pipeline

The `.pkg` container is described **once**, in Rust, at `d1-server/crates/d1-pkg`. This directory
only decompresses; it never parses the container.

```sh
d1-pkg extract-block ps4_investment_globals_012c_1.pkg 234 -o blk.z   # stored bytes, SHA-1 checked
./oodle-decompress.py blk.z blk.bin                                   # decompress
d1-pkg verify-plain ps4_investment_globals_012c_1.pkg 234 --plain blk.bin
```

## Why this matters

76% of package blocks are Oodle LZH/LZHLW (measured: 532,600 of 701,164) and there is no public
decoder. Investment message **503** is mandatory - proven by the decode-skip probe, see
`historicaldocs/design/character-and-orbit.md` §7 - and its argument schema lives in
`ps4_investment_globals_012e_2.pkg`, which is 515/515 compressed. Without this, `investment_signin`
is unreachable.

### How that check works, and why it is not circular

The block record's `sha1[20]` covers the **stored** bytes, compressed ones included (verified
corpus-wide by `d1-pkg verify --blocks`; 340/340 on the first package tried). **Nothing in the
container stores a digest of decompressed output**, so there is no Bungie-shipped digest to check the
decoder against - an earlier note here claimed the opposite and sent a verification attempt down a
dead end. That claim is **withdrawn**.

What exists instead: most payload classes open with a `u64` length, and the **entry table** declares
that same length in a completely separate structure the decompressor never reads. Agreement is
therefore independent evidence, and a chance match on any single entry has probability ~2⁻⁶⁴.

Two populations carry no length header and are excluded from scoring:

- **raw blobs** - `class_tag == 0xffffffff`, or any entry that a same-package record points at
- **self-classed records** - `class_tag` names an entry *in this same package* rather than an
  external class definition; these open with structure, not a length

**The exclusion is computed from the entry table alone and never looks at decoder output.** That is
what keeps it honest: a broken decoder cannot classify away its own failures. The rule was narrowed
twice - first keyed on a byte constant in the payload (wrong: it reads decoder output, and it broke
on `ps4_globals_pvp_0169_3`), then on a fixed 60-byte size (wrong: the same pattern occurs at 16,
120 and 128 bytes). Both earlier forms are recorded in the git history of `d1-pkg` as traps.

### Two facts this verification produced

1. **A block decompresses to *at most* `0x40000`, not always exactly.** `ps4_globals_pvp_0169_3`
   block 561 consumes all 65479 stored bytes at **114688** plain bytes. A loop that terminates on
   *output size* then calls `DecodeSome` with no input left and reads unmapped memory - which looks
   exactly like a decoder fault and is not one. **Terminate on input exhaustion.**
2. **Entries span blocks.** An entry can start inside a block and continue into the next one;
   `verify-plain` reports these as `spills`.
