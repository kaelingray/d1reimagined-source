The recovery scan covers logical metadata/padding outside listed payloads. It
does not cover physical disk free sectors, every embedded asset or retail-update
decryption. Converter completion, a static codec or a synthetic server response
cannot establish game boot or playability.

Useful contributions include:

- Reproduce source-only controls and improve portable build instructions.
- Review the existing Windows/WSL platform contract and canonical launcher;
  implement and demonstrate guest transport without weakening isolation.
- Review the package ownership resolver and guarded recovery adapters with
  synthetic inputs. Keep crypto/hash verification and build-identity gates intact.
- Work on protocol state machines and objective/inventory semantics using
  reproducible fixtures you have permission to share.
- Investigate RPCS3 graphics patches against their external source baseline,
  measuring both stability and actual rendered output.

Open a focused issue with the observed failure, source commit, proposed scope
and validation. Bring your own authorized inputs for native work; do not upload
them. The publication preserves historical observations separately from current
local acceptance, and excludes private production requirements and raw evidence.
